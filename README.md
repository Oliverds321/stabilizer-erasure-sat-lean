# A subexponential algorithm for the erasure logical error rate of sparse stabilizer codes

Lean 4 formalization, manuscript and computed examples for

> Oliver D'Souza, *A subexponential algorithm for the erasure logical error rate of
> sparse stabilizer codes*, preprint, November 2026
> ([`paper/quantum-erasure-reliability/manuscript.pdf`](paper/quantum-erasure-reliability/manuscript.pdf)).

Status: preprint, not independently refereed.

## Main results

For a stabilizer code with check matrix `H` on `n` qubits, let `F_H(p)` be the
entanglement fidelity of the optimal flagged-erasure decoder when every qubit is
lost independently with probability `p`, and `I_H = 1 - F_H` the logical error
rate. Both are polynomials in `p` of degree `n`.

- **Theorem 1 and Corollary 3** — `QecReliability.IidErasure.iid_erasure_machine_guarantee`
  (`lean/IidErasureTheorem.lean`). One fixed machine, composed with OpenAI's
  machine-checked subexponential 3-SAT algorithm, reads the check rows of an
  isotropic stabilizer code, an accuracy `ε`, a confidence `δ` and a string of coin
  bits. On every coin string it halts within the stated time and space bounds and
  outputs the coefficients of a monotone polynomial whose endpoints are exact; with
  probability at least `1 - δ` over the coins this polynomial approximates both
  `F_H` and `I_H` to relative error `ε` simultaneously at every `p ∈ [0,1]`. The
  flag decoder is proved optimal over all recoveries. The running time is
  `poly · 2^{O(n (log log n)^2 / sqrt(log n))}` with polynomial space, without any
  unproved hypothesis. The same guarantee for an arbitrary SAT engine, with its
  running time as a parameter, is
  `QecReliability.TensorMachine.Runtime.tensor_machine_guarantee`.
- **Proposition 2** — `QecReliability.IidErasure.iid_erasure_machine_guarantee_resources`:
  the query count, the bit length and the size of every SAT query (linear in the
  size of the code).
- **Hardness** — `QecPhysical.Stabilizer.Lift.distance_determination`,
  `QecPhysical.Stabilizer.Uncorrectable.infidelity_point_determines_distance`,
  `QecReliability.SatReduction.sat_iff_point` and the modules `SatCosetWeight`,
  `SatToDistance`, `SatLogicalQubit`, `SatHardness`, `DistanceExtraction`: any output
  meeting the guarantee, and even a single value of `I_H` at a small explicit `p`
  known up to an exponential factor, determines the code distance; an explicit
  reduction maps a CNF formula to a code with one logical qubit whose distance
  decides its satisfiability.
- **Extensions** — correlated erasures generated by linear-size circuits from latent
  bits (`...isotropic_polynomial_endpoint_machine_guarantee`,
  `QecReliability.LatentMonotone.latent_monotone_machine_guarantee`), several
  probability classes (`...isotropic_tensor_machine_guarantee_strong`,
  `...isotropic_tensor_machine_guarantee_general`), and the probability of an
  uncorrectable erasure (`QecReliability.UncorrectableMachine.uncorrectable_machine_guarantee`).
- **Computed examples** — the identities behind the estimator of Section 7, and a
  formula whose unsatisfiability proves that a list of minimal uncorrectable sets is
  complete (`CompletenessFormula`, `CompletenessConverse`,
  `QecPhysical.Stabilizer.ListCertificate.symmetric_certificate`), checked for
  concrete codes by `tools/lrat/CertifyList.lean` and `tools/lrat/CertifyCode.lean`.

## Checking

The compiled graph has 6,157 modules: this development, Mathlib `d13f23b7` with its
dependencies, and OpenAI's solver at commit `4eaee875`. It is compiled module by
module with Lean 4.34.1 and is not a `lake` project. [`docs/BUILD.md`](docs/BUILD.md)
gives the toolchain, the pinned dependencies, the compiler options of every module
and the memory needed (one Lean process on the solver graph peaks near 7 GiB). It
has been built on Windows 11 only.

Once the modules are compiled:

- `tools/audit/FinalTheoremsAudit.lean` prints the axioms of the 147 theorems cited in
  the manuscript, by name;
- `tools/audit/ModuleAudit.lean` collects the axioms of every declaration of the
  34 final modules (2,386 declarations) and fails on any axiom other than
  `propext`, `Classical.choice` and `Quot.sound`;
- `leanchecker MODULE` re-checks every declaration of a module in the Lean kernel.

Both audits report only the three standard axioms, and the kernel replay of all
6,157 modules passes.

## Experiments

`experiments/erasure/` contains the code and the results (JSON) of the computed
examples of Section 7: logical error rates down to `10^-28` for surface, toric and
bivariate bicycle codes of up to 128 qubits, with the distance, the minimum-size
failure sets and the leading coefficient certified by checked LRAT refutations. See
its README for what is and is not guaranteed by each result.
`experiments/hardness/` contains brute-force checks of the SAT-to-distance
reduction (evidence only; the theorems are proved in Lean).
